## ✅ 已修正（commit `fbef131`，2026-04-03 22:19）

### 問題：`strandedQuantity` 在轉入訂單前顯示錯誤，轉入後也先暫時錯誤

#### 完整實測流程（2026-04-03）

| 步驟 | `remainingQuantity` | `strandedQuantity` | 來源 |
|------|--------------------|--------------------|------|
| 轉入訂單前（DR 已建立） | 5 | **12**（正確歷史值）| 最新 OrderItem |
| 轉入訂單後（status: 待出貨）| **4** ✅ | **2** ❌ | 最新 OrderItem（從 DR 複製的錯誤值）|
| PUT /orders/:id 更新訂單後 | 4 | **13** ✅ | `orders.service.ts update()` 重算 |

#### 根本原因

兩條計算鏈完全獨立，互不相知：

| API | `strandedQuantity` 計算來源 | 程式位置 |
|-----|-----------------------------|---------|
| `POST /delivery-reports`（建立 DR 時） | 只查前一筆 `DeliveryReportItem` | `delivery-reports.service.ts` ~第 647 行 |
| `GET /customers/:id/water-bottle-deposits` | 只查最新 `OrderItem` | `customers.service.ts` ~第 765 行 |
| `PUT /orders/:id`（更新訂單時） | 查前一筆 `OrderItem`（正確）| `orders.service.ts` |

**問題發生點**：`POST /delivery-reports` 建立 DR 時，只看前一筆 DR 的滯留，完全不看 OrderItem 歷史。導致：

1. DR 計算出錯誤的 `strandedQuantity`（前一筆 DR 的鏈與 Order 的鏈不同步）
2. `convertToOrder` 將這個錯誤值複製到 OrderItem
3. `water-bottle-deposits` 讀到這個錯誤的 OrderItem，顯示錯誤值
4. 必須等到使用者手動 PUT 更新訂單，`orders.service.ts` 才會重新正確計算

#### 建議修正

修改 `delivery-reports.service.ts`，建立 DR item 時同時查詢前一筆 DeliveryReportItem **和**前一筆 OrderItem，取時間較新的那筆作為 `previousStranded`：

```typescript
// 查前一筆 DeliveryReportItem
const lastDRItem = await this.prisma.deliveryReportItem.findFirst({
  where: {
    customerId: customer.id,
    productId: product.id,
    deliveryReport: { reportDate: { lte: new Date(reportDate) } },
  },
  orderBy: [{ deliveryReport: { reportDate: 'desc' } }, { createdAt: 'desc' }],
  select: { strandedQuantity: true, createdAt: true },
});

// 查前一筆 OrderItem（包含直接建立的訂單）
const lastOrderItem = await this.prisma.orderItem.findFirst({
  where: {
    order: {
      customerId: customer.id,
      orderDate: { lte: new Date(reportDate) },
    },
    productId: product.id,
  },
  orderBy: { order: { orderDate: 'desc' } },
  select: { strandedQuantity: true, createdAt: true },
});

// 取時間較新的那筆作為基準
let previousStranded = 0;
if (lastDRItem && lastOrderItem) {
  previousStranded = lastDRItem.createdAt > lastOrderItem.createdAt
    ? Number(lastDRItem.strandedQuantity)
    : Number(lastOrderItem.strandedQuantity);
} else if (lastDRItem) {
  previousStranded = Number(lastDRItem.strandedQuantity);
} else if (lastOrderItem) {
  previousStranded = Number(lastOrderItem.strandedQuantity);
}

const strandedQuantity = Math.max(0, previousStranded + item.quantity - recoveredQuantity);
```

#### 影響範圍

- `GET /delivery-reports/:id` → `items[].strandedQuantity`（DR 建立當下的值偏低）
- `GET /customers/:id/water-bottle-deposits` → `strandedQuantity`（convertToOrder 後暫時錯誤，等訂單 PUT 更新後才正確）
- `GET /statistics/water-deposits` → `strandedQuantity`（同上）

## 問題六：`PATCH /orders/:id` 更新訂單時，`remainingQuantity`/`remainingAmount` 不會重新扣除

### 實測流程（宏遠科技，中性水18.9L，初始 remainingQuantity=2）

| 步驟 | 操作 | remainingQty | strandedQty |
|------|------|-------------|-------------|
| 1 | 初始狀態 | 2 | 9 |
| 2 | `POST /orders` qty=1, recoveredQty=5 | **1** ✅（扣 1） | **5** ✅ |
| 3 | `PATCH /orders/:id` qty=2→2, recoveredQty=5 | **1** ❌（應為 0，再扣 1） | **6** ✅（有重算） |
| 4 | Status PENDING→PROCESSING | 1 | 6（狀態改變不影響，正常） |

> `strandedQuantity` 在 `update()` 中有正確重算邏輯，但 `remainingQuantity`/`remainingAmount` 完全沒有處理。

### 根本原因（已確認）

`orders.service.ts` 的 `deductWaterBottleDeposit()` 只在 `create()` 第 245 行被呼叫：

```typescript
// orders.service.ts create() 第 242-247 行
if (customerId) {
  for (const item of createOrderDto.items) {
    await this.deductWaterBottleDeposit(customerId, item.productId, item.quantity);
  }
}
```

`update()` 方法中的 `toUpdate`（更新現有 item）、`toCreate`（新增 item）、刪除 item 三種情境，**都沒有呼叫 `deductWaterBottleDeposit`**。

### 影響

| 情境 | 應發生的事 | 實際情況 |
|------|-----------|---------|
| `PATCH /orders/:id` 數量增加 | 差額扣除 remainingQty | ❌ 未扣除 |
| `PATCH /orders/:id` 數量減少 | 差額退回 remainingQty | ❌ 未退回 |
| `PATCH /orders/:id` 新增商品 item | 全數扣除 remainingQty | ❌ 未扣除 |
| `PATCH /orders/:id` 刪除商品 item | 退回原數量至 remainingQty | ❌ 未退回 |

`remainingAmount` 推測有同樣問題（尚未實測，但與 `remainingQuantity` 使用相同的 `deductWaterBottleDeposit` 方法）。

### 建議修正

在 `update()` 的 items 處理邏輯中，計算每個商品的**數量差值**，並相應地扣除或退回 `WaterBottleDeposit`：

```typescript
// 在 update() transaction 結尾，items 更新完成後：
if (order.customerId) {
  // 取更新前的 items（已在 transaction 開頭查詢）
  // 計算每個 productId 的數量變化
  for (const [productId, delta] of quantityDeltaMap) {
    if (delta > 0) {
      // 數量增加 → 額外扣除
      await deductWaterBottleDeposit(order.customerId, productId, delta);
    } else if (delta < 0) {
      // 數量減少 → 退回（增加 remainingQuantity）
      await refundWaterBottleDeposit(order.customerId, productId, Math.abs(delta));
    }
  }
}
```
