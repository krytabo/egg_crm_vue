# 後端溝通紀錄 — 2026-04-01

---

### 出貨日報表品項新增「回收數量」與「滯留數量」（待討論）

**背景：**
訂單品項（`order_items`）在 2026-03-31 已新增 `recoveredQuantity` / `strandedQuantity` 欄位，並正常運作。

業主目前也在出貨日報表（`DeliveryReport`）中做每日司機送貨記錄。出貨日報表的品項（`delivery_report_items`）目前**尚未有**回收數量與滯留數量欄位。

**問題確認：**
已查後端 Prisma schema，`DeliveryReportItem` 模型目前欄位如下：

```
quantity          Int
unitPrice         Decimal
amount            Decimal
paymentTerm       PaymentTerm?
deliveryDay       Int?
actualPaymentAmount Decimal?
note              String?
```

沒有 `recovered_quantity` / `stranded_quantity`。

---

**需求說明：**

出貨日報表可轉入訂單（`isConvertedToOrder`），轉入後的 `OrderItem` 會帶上 `recoveredQuantity`，但目前在出貨日報表編輯階段無法記錄回收數量，需要等轉入訂單後才能填。

業主希望：司機在外送貨時就能在日報表中直接記錄當次回收了幾桶，不用等到轉入訂單後再補填。

---

**建議後端修改方向：**

#### 1. Schema — `delivery_report_items` 新增 2 欄

```prisma
model DeliveryReportItem {
  // ... 現有欄位不變 ...
  recoveredQuantity  Int  @default(0) @map("recovered_quantity")
  strandedQuantity   Int  @default(0) @map("stranded_quantity")
}
```

> 資料型別建議用 `Int`（整數），與訂單品項保持一致（桶數不需要小數）。

#### 2. DTO — `DeliveryReportItemDto` 新增

```typescript
@ApiPropertyOptional({ description: '本次回收數量', example: 2, minimum: 0, default: 0 })
@IsOptional()
@Type(() => Number)
@IsInt()
@Min(0)
recoveredQuantity?: number;
```

> `strandedQuantity` 不加入 DTO，由後端根據上一筆滯留值自動計算。

#### 3. 計算邏輯（`delivery-reports.service.ts`）

當出貨日報表轉入訂單時，`recoveredQuantity` 一併帶入 `OrderItem`：

```typescript
// 轉入訂單時，一併複製回收數量
sourceDeliveryReportItemId: item.id,
recoveredQuantity: item.recoveredQuantity ?? 0,
```

---

**優先順序：** 低（目前可在轉入訂單後手動填寫，出貨日報表先行跳過）

**前端待辦（等後端確認後再做）：**
- `FormPage/DesktopView.vue` 的 grid 表格新增「回收數量」欄位（可編輯整數）
- `DataList/DesktopView.vue` 展開的明細表新增「回收數量」顯示欄
