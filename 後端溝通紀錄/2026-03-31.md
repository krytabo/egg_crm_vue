### PATCH /customers/:id/water-bottle-deposits/:depositId — 修正剩餘數量/金額計算

**問題：** 編輯儲值記錄時，只更新了 `quantity`/`amount`，但沒有同步更新 `remainingQuantity`/`remainingAmount`，導致已被訂單扣除的數量/金額遺失。
- 例如原本儲值 10 桶，已被訂單扣了 3 桶，remainingQuantity = 7
- 使用者把儲值數量改成 20 桶
- 後端只更新 quantity = 20，但 remainingQuantity 還是 7
- 正確應該要是 remainingQuantity = 20 - 3 = 17

### 新需求：訂單商品品項新增「回收數量」與「滯留數量」

**背景說明：**
業主需要在訂單中針對商品追蹤「實體包裝（如水桶）尚在客戶端的數量」。
每次出貨帶走幾桶、回收幾桶，系統自動計算目前有幾桶還留在客戶家中。

**業務邏輯（滯留計算公式）：**
```
本次滯留數量 = 上一筆訂單的滯留數量 + 本次出貨數量 - 本次回收數量
```

**實際範例（同一客戶、同一商品 A）：**

| 訂單日期   | 出貨數量 | 回收數量 | 滯留數量（自動計算） |
|------------|--------|--------|-----------------|
| 2026-03-28 | 5      | 0      | 5               |
| 2026-03-29 | 5      | 2      | 8               |
| 2026-03-30 | 2      | 5      | 5               |
| 2026-03-31 | 0      | 3      | 2               |

---

#### 重要架構說明：滯留數量涉及兩支 API

`strandedQuantity`（滯留數量）是「客戶 × 商品」維度的累計值，需要同時出現在兩支 API：

| API | 說明 |
|-----|------|
| `GET /orders/:id` | 訂單品項中顯示「本筆訂單建立當下的滯留快照」與「本次回收數量」 |
| `GET /customers/:id/water-bottle-deposits` | 顯示「該商品目前最新的累計滯留桶數」，前端建單時先查此 API 得知現況 |

**前端建單流程：**
1. 前端開啟訂單新增/編輯頁，呼叫 `GET /customers/{id}/water-bottle-deposits` 顯示各商品目前的剩餘數量、剩餘金額、滯留桶數
2. 使用者填入「回收數量」（recoveredQuantity）
3. 送出後後端自動計算新的 `strandedQuantity` 並存入 order item
4. 同時更新 `water_bottle_deposits` 的 `strandedQuantity`

#### 1. Schema 修改

**`order_items` 資料表（新增 2 欄）：**

```prisma
model OrderItem {
  // ... 現有欄位不變 ...
  recoveredQuantity  Decimal  @default(0) @map("recovered_quantity") @db.Decimal(12, 3)
  strandedQuantity   Decimal  @default(0) @map("stranded_quantity") @db.Decimal(12, 3)
}
```

**`water_bottle_deposits` 資料表（新增 1 欄）：**

```prisma
model WaterBottleDeposit {
  // ... 現有欄位不變 ...
  strandedQuantity  Decimal  @default(0) @map("stranded_quantity") @db.Decimal(12, 3)
}
```

| 欄位 | 資料表 | 說明 | 來源 |
|------|------|------|------|
| `recoveredQuantity` | order_items | 本次訂單從客戶端回收的數量 | 前端使用者手動輸入，預設 0 |
| `strandedQuantity` | order_items | 此訂單建立當下的滯留快照 | **後端自動計算，不接受前端傳入** |
| `strandedQuantity` | water_bottle_deposits | 該商品目前累計在客戶端的總滯留數量 | **後端自動計算，不接受前端傳入** |

> `water_bottle_deposits.strandedQuantity` 為客戶 × 商品的單一總值；若該商品有多筆 deposit 記錄，請更新**最新一筆**（或單獨管理一個 summary 欄位）。建議後端評估是否以 computed query 回傳更乾淨（見下方第 3 點）。

#### 2. 後端計算邏輯（`orders.service.ts`）

**建立或更新訂單時**，針對每個 item 計算 `strandedQuantity`：

```typescript
// 查同一客戶、同一商品比本訂單更早的最新一筆 order_items.strandedQuantity
const lastItem = await tx.orderItem.findFirst({
  where: {
    productId: item.productId,
    order: {
      customerId,
      orderDate: { lt: thisOrderDate },
    },
  },
  orderBy: { order: { orderDate: 'desc' } },
  select: { strandedQuantity: true },
});

const previousStranded = Number(lastItem?.strandedQuantity ?? 0);
// 最小值為 0，不可出現負數
const newStranded = Math.max(0, previousStranded + Number(item.quantity) - Number(item.recoveredQuantity ?? 0));

// 同步更新 water_bottle_deposits（找該客戶+商品的最新一筆）
const latestDeposit = await tx.waterBottleDeposit.findFirst({
  where: { customerId, productId: item.productId },
  orderBy: { createdAt: 'desc' },
});
if (latestDeposit) {
  await tx.waterBottleDeposit.update({
    where: { id: latestDeposit.id },
    data: { strandedQuantity: newStranded },
  });
}
```

#### 3. `GET /customers/:id/water-bottle-deposits` 回傳格式（新增欄位）

每筆 deposit 物件新增 `strandedQuantity`：

```json
{
  "id": "...",
  "productId": "...",
  "quantity": 20,
  "amount": 1000,
  "remainingQuantity": 15,
  "remainingAmount": 750,
  "strandedQuantity": 8
}
```

> 若後端不想在 `water_bottle_deposits` 存 `strandedQuantity`，也可在 `getDeposits()` 中以 raw query 即時計算：
> ```sql
> SELECT product_id,
>        COALESCE(SUM(quantity), 0) - COALESCE(SUM(recovered_quantity), 0) AS stranded_quantity
> FROM order_items oi
> JOIN orders o ON oi.order_id = o.id
> WHERE o.customer_id = :customerId
> GROUP BY product_id
> ```
> 建議以此方案為主，較不易產生資料不一致問題。

```typescript
@IsNumber()

```
